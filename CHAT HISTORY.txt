The guard only skips renderState if answered===true. Since the team has NOT answered yet, answered is false, so renderState IS called. renderState calls renderQScreen. renderQScreen checks s.paused first — good, it should lock everything.

For the answering team however — their timer was started via your_turn with a specific timerEnd timestamp. That local setInterval in startTimer is still running because nothing stopped it.
